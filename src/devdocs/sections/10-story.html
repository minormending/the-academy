Story, quests, NPCs and the Trial Hall

This section covers the game's "things to do": quests and how their progress is tracked, the main questline that carries a student from orientation to graduation, the nine campus NPCs and the scripts that decide what they say, and the Trial Hall, a replayable wave-survival arena. The player-facing names follow the Academy theme: a quest is an Assignment, a job-advancement quest is a Year-end Exam, a repeatable boss hunt is a Field Bounty, and a step of the main questline is a story step. In code they are all the same QuestDef.

The pieces talk through the event bus (architecture). An NPC script never touches the DOM: it emits ui:dialog or ui:shop, and the dialog's buttons call back into Progression, which owns all quest state.

Quest data

export interface QuestDef {
  id: string;
  name: string;
  giver: string;           // npc id
  description: string;
  minLevel: number;
  requiredJobBranch?: Branch;
  objectives: ({ kind: 'kill'; monsterId: string; count: number } | { kind: 'collect'; itemId: string; count: number } | { kind: 'level'; level: number })[];
  rewards: { exp?: number; mesos?: number; items?: { itemId: string; qty: number }[] };
}
export interface QuestProgress { status: 'active' | 'complete' | 'turned_in'; counts: number[]; }

(types.ts:414.) A quest is pure data. The player's progress is a QuestProgress in state.quests[questId], with one count per objective. A quest that is not in that record has never been accepted.

ObjectiveHow the count moves
kill+1 per monster:killed of that monster id, only while the quest is accepted and not turned in. Never goes down.
collectRecomputed from the inventory on every add, remove, buy and sell: min(count, countItem(itemId)). Can go down (sell the items and the quest goes back to active). Handed in (removed) on turn-in.
levelmin(level, state.level), refreshed on level-up.

EXP rewards are written as a fraction of a level's requirement, so they follow the balance curve (balance.ts):

/** Quest EXP reward as a fraction of the EXP needed for `level`. */
const xp = (level: number, frac: number) => Math.round(expToNext(level) * frac);

(quests.ts:7.) Snail Patrol pays xp(2, 0.9) = 58 EXP, 90% of level 2 (which needs 64).

acceptQuest checks canAcceptQuest (no existing record, level ≥ minLevel, matching requiredJobBranch), creates the record with zero counts and evaluates it at once, so a collect quest whose items are already in the bag is immediately complete (Progression.ts:650). Kill counts are bumped in the same monster:killed handler that grants EXP, with a log line at every fifth kill and at the target (Progression.ts:181).

Turning in is atomic: either everything happens (items handed in, rewards granted, saved) or nothing does.

  turnInQuest(questId: string): boolean {
    const q = Registry.quest(questId);
    const prog = this.state.quests[questId];
    if (!q || !prog || prog.status === 'turned_in') return false;
    this.evalQuest(q, false);
    if (prog.status !== 'complete') return false;
    const rewards = q.rewards.items ?? [];
    const handIn = q.objectives.flatMap(o => o.kind === 'collect' ? [{ itemId: o.itemId, qty: o.count }] : []);
    if (!this.canFit(rewards, handIn)) {
      bus.emit('ui:log', { text: 'Make some room in your inventory first.', color: LOG.warn });
      return false;
    }
    prog.status = 'turned_in';
    for (const h of handIn) this.removeItem(h.itemId, h.qty);
    // … log + quest_complete sfx
    if (q.rewards.mesos) this.addMesos(q.rewards.mesos);
    for (const r of rewards) this.addItem(r.itemId, r.qty);
    if (q.rewards.exp) this.gainExp(q.rewards.exp);
    bus.emit('quest:updated', { questId });
    this.changed();
    this.save();
    return true;
  }

(Progression.ts:660.)

Advanced: why the turn-in order matters
  • Room is checked by simulation. canFit(rewards, handIn) copies the inventory, removes the hand-in items (smallest stacks first, like removeItem), then tries to add the rewards. Handing in 20 Yeti Fur can free the slot the reward needs, and the check knows that.
  • Status flips before items are removed. removeItem calls refreshQuests, which re-evaluates every quest that isn't turned_in. If the status were still complete, removing the collect items would flip it back to active halfway through its own turn-in. Setting turned_in first makes the quest invisible to that refresh.
  • EXP last. gainExp may level the player, which refreshes quests and saves; doing it after the items and mesos means the save it triggers already contains the whole turn-in, and the final save() covers quests that pay no EXP.
  • Kill counts don't backfill. Kills made before accepting never count, and a complete quest's maxed kill objective isn't incremented further. That is why the Field Bounty text says to take the bounty before the hunt.
  • Talk-only steps have no objectives. every() over an empty list is true, so they become complete the moment they are accepted, and the story script hands them in during the same conversation.

export function storyStepDone(v: StoryStateView, id: string): boolean {
  if (v.quests[id]?.status === 'turned_in') return true;
  const f = STORY_FLOW[id];
  return !!f?.maxTier && v.tier > f.maxTier;
}

export function storyStepUnlocked(v: StoryStateView, id: string): boolean {
  const f = STORY_FLOW[id];
  if (!f) return true;
  if (f.prev && !storyStepDone(v, f.prev)) return false;
  if (f.minTier && v.tier < f.minTier) return false;
  if (f.maxTier && v.tier > f.maxTier) return false;
  return true;
}

(storyQuests.ts:125.) tier is the current job tier, which is the school Year. The flags:

  • talk: the lesson is the conversation; accepted and handed in on the spot.
  • anyProfessor: any of the five Professors runs the step (its giver is just the one nearest the Headmistress); each gives their own School's welcome and study tip.
  • maxTier: 1: a Year 1 lesson. A student who is already past Year 1 skips it, and storyStepDone counts it as done so it never blocks the chain.
  • tag: the chapter label shown on the dialog option, e.g. "[Year 3] Ash and Ink".
Advanced: story-flow edge cases
  • Level is checked separately. storyStepUnlocked ignores level on purpose (it lives in a data module with no system imports). Callers combine it with minLevel; when only the level is missing, the giver shows a "(Lv 27)" teaser option instead of the step (storyStatus returns 'soon').
  • Declaring from either path. At level 10 Maelis offers "I am ready to declare." directly unless Declaration Day is ready to hand in, in which case the hand-in leads into the same chooseSchool flow. chooseSchool also hands Declaration Day in if it is complete, so the Scholar Cap reward is never lost.
  • The old Lich side quest. q_maelis_archon was the same deed as the Final Thesis. supersededByStory hides it once the story step is available, and handing in the Final Thesis marks the untouched side quest turned_in (retireSideArchon, npcScripts.ts:380). It really is repeatable afterwards: once the Final Thesis is handed in, Maelis lists "[Repeat] The Lich Archon (again)" and re-posts it the same way Finn re-posts Field Bounties (archonRenewOptions, npcScripts.ts:1017), so the Sigil can be farmed for the bounty reward.
  • No skipping ahead. The Year gates mean a student who never sits the Year 3 Exam stays at Pages in the Snow, however high their level.

Scripts are built from three tiny helpers:

function say(c: Ctx, text: string, options: DialogOption[] = []) {
  bus.emit('ui:dialog', { npcId: c.npcId, npcName: c.npcName, portraitKey: c.portraitKey, text, options });

const go = (label: string, fn: () => void): DialogOption => ({ label, closes: false, action: fn });

(npcScripts.ts:24.) A go option keeps the dialog open and runs a function that usually calls say again with the next page; a bye option closes it. A conversation is therefore a chain of closures, and every page is rebuilt from the current state, so it is never stale. Text can contain {key:slot0}-style placeholders that the UI replaces with the player's live key bindings (input).

Campus staff

  • Bram opens the potion shop (ui:shop with POTION_SHOP) and the Merit Exchange, a set of dialog pages (list, confirm, receipt) because the shop window only knows mesos. Purchases call buyWithMerits; prices and stock are in progression.

Quest markers

Above each NPC floats a yellow ! (something new) or a green ! (something to hand in). npcNotice decides which by checking, in order: story steps this NPC runs, side quests, Maelis's "ready to declare" at level 10, and for a Professor, the student's pending Exam (npcScripts.ts:513). A hand-in always wins over "new".

Advanced: writing and extending scripts safely
  • Re-read state inside actions. A button's action runs later than the page that drew it. storyOffer calls questStatus again after acceptQuest: a talk step is already complete and goes straight to the hand-in, and a refused accept gets "not quite yet" instead of a misleading "off you go".
  • Persist after side effects. turnInQuest saves, but a story step's after hook runs after it (the graduation Merits, for example). storyTurnIn therefore calls save() again; the final QA pass (b2a181f) added that after the graduation Merits could be lost on reload.
  • Scripts must not throw. runNpcScript wraps every script; on an exception it logs and shows "..." with a goodbye button (npcScripts.ts:1057). An NPC with no entry in SCRIPTS still offers its story and side quests with a generic greeting.
  • Adding an NPC: an NpcDef in npcs.ts, a placement in a map, and optionally a script in SCRIPTS. Quests whose giver is the new id appear in its dialog and markers automatically.
  • The script module imports Progression as a type and casts services.progression to it, because it needs helpers (questStatus, roomFor, buyWithMerits) that aren't all on IProgression.

NpcManager: placement and interaction

NpcManager turns a map's placements into sprites with a name tag, a title tag and a hidden "!" marker. If the NPC texture can't be built it draws a simple robed silhouette in the NPC's colours, so a missing asset never hides a quest giver.

  nearestInteractable(): string | null {
    const pl = this.playerPos();
    if (!pl) return null;
    let best: NpcEntry | null = null;
    let bestD = Infinity;
    for (const n of this.npcs) {
      const dx = Math.abs(n.x - pl.x), dy = Math.abs(n.y - pl.y);
      if (dx > NPC_TALK_RANGE || dy > TALK_RANGE_Y) continue;
      const d = dx + dy * 0.5;
      if (d < bestD) { bestD = d; best = n; }
    }
    return best?.id ?? null;
  }

  interact(npcId: string) {
    const n = this.npcs.find(e => e.id === npcId);
    if (n) {
      const pl = this.playerPos();
      if (pl) n.sprite.setFlipX(pl.x < n.x); // face the player (art faces right by default)
    }
    try { this.services.audio?.play('ui_open'); } catch { /* ignore */ }
    runNpcScript(this.services, npcId, n?.textureKey);
    this.noticeAcc = NOTICE_REFRESH_MS; // re-evaluate markers right away
  }

(NpcManager.ts:115.) Talk range is 90 px each way; vertical distance counts half, so the NPC on your own floor wins over one on a ledge above. GameScene calls interact when the interact key (Up by default) is pressed and no portal is in reach. In update the manager refreshes markers every 400 ms, bobs them, shows a "▲ Talk" hint over the nearest NPC, and turns NPCs back to their default facing when you walk away.

The window redraws when a signature of the quest record, level, job, inventory and key bindings changes, because collect counts depend on the bag and the quest text shows live key names. Graduation and the credits roll

Commencement is a talk step. Its after hook awards GRADUATION_MERITS (1,000) and a "Graduation Day!" banner; its rewards are the Arcane Amulet, 10 Power Elixirs and 50,000 mesos. The credits are started by the UI, not the script:

The Trial Hall

The Trial Hall (map trial_hall) is a replayable wave-survival arena. Its door is on the balcony of the Headmistress's tower on campus, reached by the ladder at x 1392 (maps.ts:54). The hall has no natural spawns and is not a safe map. ArenaSystem.ts runs the waves; the DOM panel arenaPanel.ts mounts only while you are in the hall, reads getArena()?.view() every frame and calls begin() / forfeit().

Ten waves pay 164 Merits in total. Each wave also pays bonus EXP of refMonsterExp(level) × (1 + 0.6n), doubled on boss waves: at level 30, clearing wave 5 pays 145 × 4 × 2 = 1,160 EXP. Both are paid the moment the wave is cleared, so a run that ends badly loses nothing already earned. The kills themselves give normal EXP through monster:killed.

Building a wave

  • Monster choice. planWave picks up to three normal monster types within 6 levels of the target (the three nearest if fewer qualify), and spawns them round-robin in shuffled order.
  • Boss waves use the field boss nearest the target level, within 12 below to 4 above, never the Lich Archon. With none in range, the strongest pick appears as an "Elite Champion" with ten times its wave HP. Boss HP is ×0.5 on the first boss wave and +0.25 for each later one.
  • Level normalisation. Normal monsters get (1 + 0.09(n − 1)) × clamp(refMonsterHp(target) / refMonsterHp(def.level), 1, 3) HP, because the roster tops out at level 46 while late waves target higher. Touch damage is scaled the same way with refMonsterTouch (capped at ×3), and elites hit 30% harder and have 5× HP.
  • Spawning happens one monster every 120 ms, at least 200 px from the player (bosses go to the far side of the hall). Every spawn is provoked for 60 s and the whole wave is re-provoked every 1.5 s, so nothing wanders off.
  • Personal best (state.arenaBest) is updated as soon as a wave beats it, and the run's end saves.

The death crash fix

The final QA pass (b2a181f) fixed a crash when the student died in the hall:

  constructor(private scene: Phaser.Scene, private services: GameServices) {
    current = this;
    // Death ends the run from update() (tick sees isDead), never synchronously: player:died fires mid-way through a
    // monster's own update (e.g. a boss hazard tick), and despawning that monster under its own feet breaks it.
    this.unsubs.push(bus.on('player:died', () => { if (this.running()) this.fellPending = true; }));
  }

(ArenaSystem.ts:159.) Ending the run despawns every arena monster. Done inside the player:died handler, that destroyed the monster whose own update had just dealt the killing blow, and its next line ran against a destroyed object. Now the handler only sets a flag, and the arena's next tick ends the run as 'fell', outside any monster's update.

Advanced: Trial Hall invariants and gotchas
  • Every living monster counts. The hall has no spawn groups, so enemiesLeft is simply all living monsters plus pending spawns. That includes adds a field boss summons itself, which is why the wave doesn't end while they live.
  • Arena monsters never respawn (no spawn group) and are destroyed without EXP or drops when the run ends. Leaving the hall mid-run ends it as 'left' from bindMap or clear.
  • Elite count. Since be584c4 the code adds one elite every 3 waves (1 + floor((n − 6) / 3)), and the eliteHp comment now says so too. The table above follows the code.
  • Monster HP is patched after spawn by writing maxHp and hp on the instance, and damage through an optional damageMul field, both behind casts. A Monster refactor that renames those fields would silently turn the scaling off; keep them or update ArenaSystem with them.
  • Lifecycle. GameScene constructs the system after drops, binds it after NPCs, updates it after drops, clears it on map change and destroys it on teardown. The constructor never calls services (ownership rule 4), only subscribes to the bus.
