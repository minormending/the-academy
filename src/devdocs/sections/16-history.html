How it was built

The Academy was written by a team of AI agents. One lead session (an orchestrating Claude Code session) wrote the shared contracts, owned the files that glue everything together, and handed self-contained jobs to helpers. Most helpers were builder subagents: Claude subagents started by the lead, each given a brief and a set of files it alone could edit. Some jobs went to Codex, a separate coding agent, either to build a whole feature or to review code the Claude agents wrote. The lead integrated each batch, tested it in a browser and committed it. The README says it in one line: the game was built by AI agents (Claude subagents and Codex) directed by a lead Claude session.

This section tells that story from what the repository records: git log, ROADMAP.md and ARCHITECTURE.md, which the lead extended phase by phase as the design record. Two terms used throughout:

  • A contract is a type or function signature that several agents code against, mostly in src/core/types.ts. Agents may read contracts but not change them.
  • A stub is a placeholder file that already exports the exact names and signatures the rest of the game imports, but does nothing yet. An agent "fills in" its stubs.

Every builder brief included the ground rules for builder agents. In short:

  1. Edit only your files. New files only inside your own namespace. Never touch the lead's files.
  2. Keep every stub export (name and signature compatible). Adding exports is fine.
  3. Code only against the seams: src/core/types.ts interfaces, Registry, bus and playVfx. Never import another agent's concrete class, except a short list of shared helpers (iconDataUrl, playerTextureKey, newPlayerState, getAudio…).
  4. Constructors don't call services. The services object is filled in after every service is constructed. Subscribing to bus is fine; real work happens lazily.
  5. Typecheck your own files with npx tsc --noEmit and get them to zero errors. Errors in other agents' files are not yours: they are mid-edit.
  6. No npm dependencies, no git, no dev server. The lead does the playtesting.
  7. Use the Phaser 3.60+ API (particles are scene.add.particles(…)); grep the Phaser typings when unsure.
  8. Degrade, don't throw: missing textures or data must never crash update.
  9. Report at the end: files written, public API, assumptions about other modules, and any contract problems worked around.

The team changed after Phase 1. The art pivot used new agents named PX1 (pixel characters), PX3 (world), PX4 (pixel VFX) and PX5 (pixel UI). They appear in OWNER headers such as // OWNER: PX4 (pixel VFX; formerly A10) in particles.ts. Phase 3 added a "Holy tree agent". Phase 6 added a "story agent" (storyQuests.ts), and Phase 7 added P7a (save slots) and P7b (bindings and settings, see settings.ts). Codex built ten features of its own (see below).

The lead's seams were written to tolerate missing work. playVfx in vfx.ts:17 draws a generic puff and warns once for any key that no agent has registered yet. That is how a skill agent could reference 'fire_hit' before the VFX existed. This file has not changed since the scaffold:

export function playVfx(scene: Phaser.Scene, key: string | undefined, o: VfxOptions): Phaser.GameObjects.GameObject | void {
  if (!key) return;
  const fn = registry.get(key);
  if (fn) return fn(scene, o);
  if (!warned.has(key)) { warned.add(key); console.warn(`[vfx] missing key "${key}"`); }
  const c = scene.add.circle(o.x, o.y, 10, 0xffffff, 0.8).setDepth(DEPTH.VFX);
  scene.tweens.add({ targets: c, scale: 2.5, alpha: 0, duration: 250, onComplete: () => c.destroy() });
}

The resume protocol

A long build will hit usage limits. When it does, the session stops mid-phase, and a resumed or fresh session has to work out what was going on. ROADMAP.md answers that with a five-step resume protocol:

  1. Read ROADMAP.md, ARCHITECTURE.md and git log --oneline | head -30.
  2. Run git status. Uncommitted work from an interrupted agent gets typechecked: commit it if it compiles and matches a phase, otherwise note it and redo that task.
  3. Check for still-running agents (their completion notices arrive on their own) and never start a duplicate.
  4. Start the first phase that is not [x], dispatching parallel agents under the ownership rules (disjoint files; the lead owns src/core/*, src/scenes/*, src/main.ts).
  5. After each phase: typecheck, build, smoke test, commit, tick it in the roadmap.

The status markers [x] done, [~] in progress and [ ] pending are the state machine. The bookkeeping commits (0978bb9 "Trial Hall done, Phase 6 in progress", c889a24 "Phase 7 started", a8522e0 "Phases 5 and 7 complete; Phase 8 underway") exist so the next session reads the truth from the file.

Ownership over time, and the re-theme

Ownership moved as the work changed shape. The art pivot (Phase 2) kept gameplay code fixed and asked new agents to load licensed pixel art into the existing texture keys, frame layouts and animation keys ("Art pivot", rule 1). So A10's character and particle files passed to PX1 and PX4, and PX5 added a pixel layer to A10's icon painter, A8's title screen ("pixel pass by PX5") and A2's damage numbers. Later, A9's save system got slots "by P7a". The OWNER headers record both owners, e.g. SaveSystem.ts:1.

The biggest change was the Phase 4 re-theme from "Arcana Story" to The Academy. Every player is now a student, job tiers are school Years, the town is the campus, and quests are Assignments. The rule in ARCHITECTURE.md was that save keys and all ids stay unchanged, because ids are what a save stores. The code still shows this:

  • The campus map is still mistvale, and maps.ts opens with "map ids are save data — never rename them".
  • The save key is still 'arcana-story-save-v1' (constants.ts:32), and the debug global is still arcana.
  • NPC ids kept their old names behind new titles: elder_maelis is Headmistress Maelis and scout_finn is Prefect Finn.
  • When the repeatable Lich quest needed a new name in Phase 6 (4791d48), only its name changed (to "Bounty: The Lich Archon (Repeat)"). The id stayed q_maelis_archon.

Advanced: what made parallel agents work
  • Disjoint files. No two agents ever owned the same file, so there were never merge conflicts. The lead integrated by copying work in, not by merging. When a feature crossed areas (the familiar, the Trial Hall), it was split into a contract change (lead), a new file (agent) and a wiring change (lead).
  • Frozen contracts. types.ts changed in six commits, always by the lead and always before the work that needed it. An agent that wanted a new field reported it instead of adding it, so ten agents never saw ten versions of the contract.
  • Stubs with exact signatures. Because every import resolved from the first commit, npx tsc --noEmit worked for everyone at once. An agent could check "my files have zero errors" while the files around it were still empty.
  • Four seams, all forgiving. Registry (look up data by id), bus (events instead of direct calls), playVfx (string keys with a fallback puff) and the GameServices interfaces. A skill could name a VFX key, a monster could drop an item id, and a map could place an NPC id that a different agent was still writing. Missing pieces produced a warning, not a crash. Unknown drop items still render, with a fallback texture.
  • Shared numbers, not shared code. balance.ts gave every agent the same reference curves (refMatk, refMonsterHp, per-tier skill-% bands). The fire tree and the monster roster were tuned in parallel and still met in the middle. See Progression.
  • "Never assume a texture exists — ensure it." The Phase 8 lazy-art rule (ARCHITECTURE.md) made texture generation idempotent and on-demand (ensureOnce, lazyRegister, ensureMonsterTexture). Load order between agents' generators stopped mattering. See Art.
Advanced: what went wrong, and how it was caught

Every bug below is in the log. Each one sat at a seam between two agents' work, or between the code and real hardware, which is exactly where a single agent's typecheck can't look.

  • Lost taps. Phaser clears a key's "just down" flag on keyup, so a tap shorter than one frame never cast. 6492f47 latched presses from 'down' events in GameScene, and much later e8d3158 added a cast buffer for taps during a cast lock. Found by playing, not by types.
  • Novas centred on the staff. The engine's cast origin is the staff tip, 18 px in front of the mage. aoe_self areas were centred there, so novas looked off-centre. 5bc80f6 added centerX (the body) to the attack origin and centred aoe_self on it.
  • Leaks between owners. A UI subscriber to the pixel icon sheet was never released (67893fe made onPixelIconsReady return an unsubscribe function). Looping tweens outlived their containers (5bc80f6 added loopWhileAlive).
  • A contract applied twice. Phase 3 defined curse as "deals ×(1−p) contact damage". The field-boss hazard code applied outgoingDamageMult() to damage that already included it. The final QA (b2a181f) removed the second multiplication, commented "curse already applied".
  • Re-entrancy. In the Trial Hall, a field boss's telegraph could kill the player, which despawned the boss while it was still iterating its own telegraph list. b2a181f iterates snapshots and returns early once destroyed is set.
  • Requires chains too deep. Several Year-4 primaries required a Year-3 spell at level 10, so a fresh Year-4 student couldn't learn one. 81b17e1 lowered those to level 5 (e.g. fire_inferno_lance now requires fire_orb 5).
  • Reserved keys. Rebinding could swap Esc onto another action and leave no way to close windows. Fixed in 1e80a33.
Advanced: lessons for extending the game with agents
  • Write the contract change yourself, first, in its own commit. Then brief agents against the committed contract. A widened union (Element, Branch, SfxKey) makes the compiler list every Record<Element, …> that needs an entry, so tsc becomes the checklist (see Add a School).
  • Hand out files, not tasks. A brief should name the files an agent owns, the stubs it must keep, the seams it may use, and what to report. If two tasks need the same file, either sequence them or split the file first.
  • Keep the lead's files few and boring. GameScene, skills/index.ts and registry.ts are wiring. The less logic lives there, the less the lead becomes a bottleneck.
  • Budget a QA pass per phase. Every phase in the log ends with fixes that only a browser run could find. Typecheck, npm run build and a smoke test are the minimum.
  • Treat ids as forever. Rename text, never ids: saves, quests, maps and spawn tables all refer to them by string.
  • Keep the roadmap honest. A resumed session trusts ROADMAP.md and git status over memory. Tick items only after the commit that lands them.
