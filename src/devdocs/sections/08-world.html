World and maps

A map is one side-scrolling level: a wide rectangle of ground, floating ledges, ropes and portals, with monsters and NPCs placed on it. Every map is plain data, a MapDef object in src/data/maps.ts. At run time loadMap() in src/world/MapLoader.ts turns that data into a map instance: invisible physics bodies the player and monsters stand on, plus the layered pixel art you see (sky, parallax hills, decor, terrain, ropes, portals, weather). This section covers the data format and the eight maps, how the loader builds and tears down a map, the per-theme presentation config, the world art pipeline, and the minimap.

Two rules shape everything here. First, physics and visuals are separate: the bodies come only from the numbers in the MapDef, and a texture that fails to load or paint never changes where you can walk. Second, map ids are save data: the save stores state.mapId, and portals refer to other maps by id, so an id can never be renamed (the campus is still called mistvale from before the game became The Academy).

MapDef: a map as data

The contract lives in types.ts:346. Coordinates are world pixels, x to the right and y downward, and every y you see in map data is a walking surface or a pair of feet, never the top of a sprite.

PieceMeaning
PlatformDefA horizontal span at height y (its walking surface). oneWay: true is a one-way platform: you can jump up through it from below and land on top, and Down+jump drops you through (see Physics). oneWay: false is solid ground: a column from y to the bottom of the map.
WallDefA solid block (x, y is its top-left). Its top is walkable, so walls double as raised steps and plateaus.
RopeDefA climbable vertical line at x from top to bottom; kind only changes the art (rope or ladder).
PortalDefA door at feet position (x, y). Pressing Up near it loads targetMap and places you on that map's portal targetPortal. hidden skips the visual and the minimap marker.
SpawnDefKeep count monsters of monsterId alive somewhere in x1..x2 standing on y; respawn each one respawnMs after it dies (see Monsters).
levelRange, safeShown in the minimap header and the arrival banner; safe maps spawn nothing.

The eight maps

The top of maps.ts states the conventions every map follows, then a handful of one-line helpers keep the map literals short:

Map ids and portal ids are referenced from saves (mapId), from other maps' targetMap/targetPortal, from quests and from FIELD_BOSSES[id].mapId. Renaming one silently breaks a portal or strands a save. Add new ids; never rename old ones.

Loading a map

All map changes go through GameScene.changeMap(mapId, portalId?) (GameScene.ts:96). It fades the camera out, then loadMapNow (GameScene.ts:139) tears down the old map's world, builds the new one and binds every service to it. A request that arrives during the fade (for example a respawn while a portal fade is running) replaces the pending destination instead of starting a second fade.

loadMap itself is small. It looks the id up in the Registry, falls back to the first map with a warning, and constructs a MapInstance (MapLoader.ts:24):

export function loadMap(scene: Phaser.Scene, mapId: string): IMapInstance {
  const def = Registry.map(mapId) ?? MAPS.find(m => m.id === mapId) ?? MAPS[0];
  if (!def) throw new Error(`[map] no maps defined`);
  if (def.id !== mapId) console.warn(`[map] unknown map ${mapId}, loading ${def.id}`);
  return new MapInstance(scene, def);
}

Solids, one-way platforms and walkables

Phaser's Arcade physics works with axis-aligned boxes. A static body never moves and is cheap to collide against; a static group is a collection of them that one collider call can test at once. The loader makes two groups, and the player and ground monsters add a collider against each (flyers and field bosses skip the one-way group):

  • solids: ground columns, walls and two invisible edge walls just outside the map.
  • platforms: one-way platforms. Each is a 12 px tall box (ONE_WAY_BODY_H) whose checkCollision is turned off on the bottom, left and right faces, so only landing on top collides.
  private buildPhysics() {
    const H = this.heightPx, W = this.widthPx;
    for (const p of this.def.platforms) {
      const w = Math.max(1, p.x2 - p.x1);
      if (p.oneWay) {
        const z = this.zone(this.platforms, p.x1, p.y, w, ONE_WAY_BODY_H);
        const b = z.body as Phaser.Physics.Arcade.StaticBody | null;
        if (b) { b.checkCollision.down = false; b.checkCollision.left = false; b.checkCollision.right = false; b.checkCollision.up = true; }
        z.setData('platform', p);
      } else {
        // solid column from the surface to below the map bottom
        const z = this.zone(this.solids, p.x1, p.y, w, Math.max(32, H - p.y + 200));
        z.setData('platform', p);
      }
    }
    for (const wl of this.def.walls ?? []) this.zone(this.solids, wl.x, wl.y, wl.w, wl.h).setData('wall', wl);
    // map-edge walls (outside the map) so nothing walks off the sides even without world-bounds collision
    this.zone(this.solids, -64, -600, 64, H + 1200);
    this.zone(this.solids, W, -600, 64, H + 1200);
  }

(MapLoader.ts:231.) The bodies are Phaser zones: invisible game objects that exist only to carry a body. Nothing visual is attached, which is why art can never move a collision edge.

Before the bodies, buildWalkables() (MapLoader.ts:203) computes walkables: the spans you can actually stand on. A platform that a wall stands on is split around the wall, and each wall's top is added as its own solid span. Monster edge checks, decor scatter and groundYAt all use this list rather than the raw platforms, so a monster walking along the Whisperwood floor treats the hill wall as the end of its span instead of walking into it.

Ropes and portals have no bodies. They are lines and points in the MapDef, and other systems ask the map instance about them through IMapInstance (types.ts:373):

  platformAt(x: number, y: number, tolerance = 12): PlatformDef | null {
    let best: PlatformDef | null = null, bestD = Infinity;
    for (const p of this.walkables) {
      if (x < p.x1 || x > p.x2) continue;
      const d = p.y - y;              // >= 0: surface at/below the point
      if (d < -tolerance || d > tolerance) continue;
      const score = d >= 0 ? d : -d + 0.5; // prefer at/below
      if (score < bestD) { best = p; bestD = score; }
    }
    return best;
  }

(MapLoader.ts:133.) The + 0.5 breaks ties: when a monster's feet are exactly between two surfaces, the one under it wins. GameScene checks for a portal before an NPC, and skips both while the player is climbing (GameScene.ts:310), so Up on a rope next to a portal climbs instead of warping.

The portal visual is a separate class, PortalVisual (portals.ts:8). With the pixel art loaded it plays the 8-frame w_portal_spin animation on a pad with square sparkles; otherwise it falls back to two counter-rotating procedural swirls squashed into an oval by a container. Either way a ▲ hint arrow fades in when the player's feet are within 48 px horizontally and 90 px vertically. That window is a little larger than PORTAL_REACH, so the arrow appears just before Up starts to work.

Advanced: map design rules and why they hold
  • 90 px tiers come from the jump arc. GRAVITY is 1500 px/s² (constants.ts:4) and the base jump velocity is 560 px/s (tuning.ts:6). The apex is v²/2g = 560²/3000 ≈ 105 px. A ledge 90 px up leaves about 15 px of margin for the feet to clear the 12 px one-way body and land; anything taller gets a rope or ladder. Air time is 2v/g ≈ 0.75 s, so at the base walk speed of 200 px/s a jump covers about 150 px, hence the "horizontal gaps ≤ 120 px" rule in ARCHITECTURE.md. Movement buffs only add margin.
  • Rope ends are offset on purpose. rope() stops 8 px above the lower surface and ladder() 2 px above. On Up the player probes points 12, 30 and 50 px above its feet (Player.ts:592), so from the lower floor the first probe already lies on the rope. top equals the upper surface so climbing off the top lands on it.
  • Spawns live on real surfaces. on() insets the range 40 px from both platform edges, and MonsterManager further clamps by half the monster's width, so nothing spawns hanging off an edge. A spawn whose y is not a surface still works (the monster falls to the next one), but its edge checks will be wrong until it lands.
  • Keep portal mouths clear. Field boss spans and big spawn spans start well inside the map (Whisperwood's boss span is 1740–2950 with portals at 70 and 3130). Monsters also refuse to wander within 110 px of a portal (see monster AI), and field-boss arenas are cut 150 px either side of one.
  • maps.ts has no runtime imports (only import type), so a plain Node script can load it and lint the geometry, for example "every one-way tier is ≤ 90 px above the surface below it or has a rope".
  • Unknown ids degrade, they do not crash. changeMap refuses an id the Registry does not know; loadMap falls back to the first map; an unknown portalId falls back to getDefaultSpawn().

On top of the seeded scatter, MAP_EXTRAS (mapExtras.ts:35) holds hand-placed set dressing per map: the campus buildings and School halls, signposts and lamps at portals, waterfalls and lava falls (falls), x-ranges kept free of scatter (clearZones), a scatter density multiplier, and the default spawn (campus (1200, 980), Sanctum (200, 980), Trial Hall (160, 780)). The scatter in buildDecor (MapLoader.ts:409) is seeded with rng(hashStr(def.id + ':decor')), a small deterministic random generator, so a map looks the same on every visit. It walks each solid span placing big back pieces, medium fillers and small front bits at theme-specific spacings, then dresses one-way platforms at least 150 px wide (and hangs vines or icicles under those at least 120 px wide), skipping 90 px around portals, 60 px around NPCs and anything near a rope.

Ambient weather

Ambient (ambient.ts:35) turns the theme's AmbientKind[] into particle emitters. The emitters sit at world (0, 0) and never move; only their emit zone (the rectangle new particles appear in) follows the camera each frame. Particles already in the air therefore stay put in world space while you walk past them, which is what makes leaves feel like they are in the world rather than glued to the screen.

    for (const l of this.live) {
      if (l.mode === 'view') l.rect.setTo(vx - 80, vy - 60, vw + 160, vh + 120);
      else if (l.mode === 'top') l.rect.setTo(vx - 260, vy - 40, vw + 420, 24);
      else l.rect.setTo(vx - 100, vy + vh + 10, vw + 200, 30);

(ambient.ts:239.) view mode fills the screen (fireflies, spores, motes), top emits from a strip above it (leaves, petals, snow, ash, rain) and bottom from below (embers). Three frames after a map loads, each emitter is fastForwarded by its pre-warm time so the screen is already full of snow when the fade lifts. Every emitter has a maxAliveParticles cap; the largest is rain at 220. When the pixel art is loaded, pixelize() rounds particle scales to whole numbers and removes rotation so the squares stay crisp.

Storm lightning is not a particle. A full-screen sky flash, an additive overlay flash and a bolt drawn with Graphics (stepped 4 px blocks in pixel mode) fire every 6–15 s (the first after 4–9 s). The flash is a double pulse (0–90 ms, 160–260 ms, then fading out by 600 ms), and the thunder sound follows 250–750 ms later at volume 0.18.

Backgrounds and parallax

Parallax is the illusion of depth from background layers that scroll slower than the foreground. Every backdrop layer here is a TileSprite (a texture that repeats inside a fixed rectangle) pinned to the screen with setScrollFactor(0). Instead of moving the sprite, MapInstance.update shifts the texture inside it:

      const maxScrollY = Math.max(0, this.heightPx - cam.height);
      const climb = Math.max(0, maxScrollY - cam.scrollY);
      for (const l of this.layers) {
        const tx = cam.scrollX * l.fx + (l.drift ? this.elapsed * l.drift : 0);
        if (l.k) {
          l.obj.tilePositionX = Math.round(tx / l.k);
          l.obj.y = Math.round((l.screenTop + climb * l.fy) / l.k) * l.k;
        } else {
          l.obj.tilePositionX = tx;
          l.obj.y = l.screenTop + climb * l.fy;
        }
        if (l.fills) for (const f of l.fills) f.obj.y = l.obj.y + f.dy;
      }

(MapLoader.ts:162.) fx is the horizontal factor: a far mountain range at 0.05 moves 5 px for every 100 px the camera moves. climb is how far the camera is above the bottom of the map, and fy lets a layer sink as you climb ropes, so the hills drop out of view as you reach the top tiers. drift auto-scrolls clouds.

There are two backdrop builders. buildPixelBackdrop() uses the 16-bit strips listed per theme in PIXEL_BG (manifests/world.ts:50): 2 to 5 layers, each with a source size, an integer display scale k (2, 3 or 4), its screen y, fx/fy, and solid fill colours above and below so a tall camera never sees a gap. If the theme's sky strip did not load, it returns false and buildBackdrop() uses the procedural 1024×512 painted layers and the THEME_RUNTIME factors instead.

Advanced: pixel snapping and depth
  • Why divide by k. A pixel layer is drawn at setScale(l.k), so tilePositionX is measured in source pixels. Rounding tx / k moves the strip in whole source pixels, so one art pixel always covers exactly k×k screen pixels. Rounding tx instead would let the strip sit at a fraction of an art pixel and shimmer as it scrolls. The y position is rounded to a multiple of k for the same reason.
  • Integer scales only. PIXEL_SCALE is 2 for foreground art (constants.ts:37); parallax strips may use 3 or 4 to fill the screen. placeDecor ignores a decor entry's scale for pixel textures (they are pre-baked ×2), short one-way platforms crop their end caps rather than stretch them, and pixel waterfalls snap their width to the 48 px tile so the texture never seams mid-fall.
  • The procedural fallback insets 2 rows (TERRAIN.layerH - 4 tall, tilePositionY = 2) so linear filtering never wraps the opaque bottom row onto the top edge.
  • Depth bands come from DEPTH (constants.ts:8): sky −1000, parallax −900/−800/−700, terrain 0, decor 5, ropes 6, portals 7, then NPCs, drops, monsters and the player. Pixel strips stack at PARALLAX_FAR + i × 40, so a five-layer stack (storm) reaches −740 and still sits behind the falls at PARALLAX_NEAR + 20. Decor layer maps to far/back/mid/front depths around TERRAIN.
  • The camera follows with lerp 0.12 and a 40 px vertical offset (cam.startFollow(…, 0.12, 0.12, 0, 40)), so scrollX is fractional most frames; all the rounding above happens after the parallax multiply, never before.

World art: tiles, terrain, decor and the town

Every world texture is made once at boot by generateTileTextures() (tileArt.ts:14), called from BootScene. It runs six painters in order, each in its own try, and finally creates a 1×1 marker texture w__ready. The loader checks that marker and calls the generator itself if boot skipped it, so a map can always be built.

  const steps: [string, (s: Phaser.Scene) => void][] = [
    // 16-bit pixel art from the loaded source packs first; the procedural painters below skip existing keys
    // and so only fill in whatever failed to load.
    ['pixel', generatePixelWorldTextures],
    ['terrain', generateTerrainTextures],
    ['parallax', generateParallaxTextures],
    ['decor', generateDecorTextures],
    ['town', generateTownTextures],
    ['fx', generateFxTextures],
  ];

The order is the fallback mechanism. generatePixelWorldTextures (pixel.ts:92) takes the source PNGs that BootScene.preload queued from the world manifest and bakes them, integer-upscaled with smoothing off, into the final texture keys. The procedural painters run next, and makeTex (util.ts:10) skips any key that already exists. Whatever PNG failed to load is therefore painted procedurally under the same key, and the loader never knows the difference. PIXEL_KEYS records which keys came from pixel sources so the loader can keep those at integer scale.

function bake(scene: Phaser.Scene, key: string, img: CanvasImageSource, sx: number, sy: number, sw: number, sh: number, k = S): boolean {
  try {
    if (scene.textures.exists(key)) return true;
    const tex = scene.textures.createCanvas(key, sw * k, sh * k);
    if (!tex) return false;
    const ctx = tex.getContext();
    ctx.imageSmoothingEnabled = false;
    ctx.drawImage(img, sx, sy, sw, sh, 0, 0, sw * k, sh * k);
    tex.refresh();
    PIXEL_KEYS.add(key);
    return true;
  } catch (e) {
    // …
  }

Terrain drawing in buildTerrain (MapLoader.ts:474) follows the physics, not the other way round: each solid platform becomes a soil TileSprite from just under its surface to below the map bottom, topped by a lip strip whose grass row lines up with y; walls get a wall tile, side shading and a cropped lip; one-way platforms get a tiled middle and two end caps that overhang the body by capOverhang. Glows (lamps, braziers, crystals, hall windows) are additive w_glow images placed by DECOR_GLOWS, with separate anchors for the pixel sprites in PIXEL_GLOW_DY. The minimap

The minimap (src/ui/minimap.ts) is a DOM canvas in the UI overlay, not a Phaser object. When the map changes it draws a static layer once, from the MapDef alone: walls as blocks, dashed ropes, platforms as lines (solid ground thicker and green, one-way thinner and blue), glowing portal dots (hidden portals skipped) and NPC dots. The map is scaled to fit 216 × 112 CSS px and drawn at 2× for sharp lines. Every 80 ms (about 12 times a second) it blits that layer and adds live dots for monsters (bosses larger and pink) and a pulsing dot for the player. The header shows the map name and either "Safe zone" or the level range. M (or its rebound key) collapses it, and the choice is remembered. See UI for the overlay.

Teardown on map change

A map instance owns everything it created. Every visual goes through keep() into one array, portal visuals and the ambient system keep their own lists, and destroy() (MapLoader.ts:189) releases all of it:

  destroy() {
    if (this.destroyed) return;
    this.destroyed = true;
    try { this.ambient?.destroy(); } catch { /* ignore */ }
    for (const pv of this.portalVisuals) { try { pv.destroy(); } catch { /* ignore */ } }
    for (const o of this.visuals) { try { o.destroy(); } catch { /* ignore */ } }
    try { this.solids.destroy(true); } catch { /* ignore */ }
    try { this.platforms.destroy(true); } catch { /* ignore */ }
    this.visuals = []; this.layers = []; this.fixedSky = []; this.pulsers = []; this.bobbers = []; this.scrollers = [];
    this.portalVisuals = []; this.ambient = null;
  }
Advanced: memory, ordering and failure isolation
  • Textures are shared, objects are not. World textures are generated once per session and reused by every map, so a map change destroys game objects (sprites, tile sprites, rectangles, graphics, emitters, zones) but frees no textures. That keeps map changes fast and makes revisits free. The cost is that every world texture stays in memory for the whole session.
  • Order matters. loadMapNow clears skills, monsters, drops, NPCs and the familiar before map.destroy(). Monsters hold colliders against map.solids and map.platforms; destroying a monster removes its colliders first, so no collider is left pointing at a destroyed static group. If you add a system that collides with the map, clear it in the same block.
  • destroy(true) on a static group destroys its zones as well as the group. Without true the zones would linger in the scene's display list.
  • Idempotent and guarded. destroy() returns early the second time (scene shutdown also calls it), and update() does nothing once destroyed is set. update() wraps its whole body in one try and warns only once per instance, so a bad decor bobber can't flood the console 60 times a second.
  • Timers are not the map's job. Respawn and field-boss timers belong to MonsterManager, which bumps a generation counter on clear() so a timer created for the previous map does nothing when it fires (see MonsterManager).
  • Extending safely. A new visual must be created through keep() (or tracked by a helper with its own destroy), must check this.has(key) before using a texture, and should run inside one of the constructor's try steps. A new map needs only a MapDef in MAPS, a theme, and optionally a MAP_EXTRAS entry; see Recipes.
