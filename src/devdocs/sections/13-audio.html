Synthesized audio

The game ships no audio files: no MP3, OGG or WAV anywhere in public/. Every sound is built at the moment it plays from WebAudio nodes (the browser's audio graph API): oscillators, a looping noise buffer, filters and gain envelopes. Music is the same voices driven by a small step sequencer reading songs written as text. This section covers the four files involved:

FileRole
AudioSystem.tsThe IAudio service: context unlock, buses, volumes, SFX rate limits, music crossfades. One shared instance.
audio/synth.tsThe toolkit: tone, noise, bell, envelopes, note names.
audio/sfx.tsOne recipe function per SfxKey, plus per-key gain and rate limits.
audio/music.tsEight songs in tracker notation and SongPlayer, the lookahead sequencer.

Terms used below: a voice is one sounding note (an oscillator or noise source plus its gain node); an envelope is the gain curve over a voice's life (attack up, optional hold, release down); a bus is a gain node many voices connect to, so their volume can be changed in one place.

AudioSystem: one context, two buses

Both scenes and the UI use the same instance through getAudio() (AudioSystem.ts:177): TitleScene and the title menu import it directly, and GameScene stores it as services.audio. A singleton matters here because an AudioContext is expensive and, more importantly, can only start after a user gesture; creating it once and keeping it across Title → Game → Title means the player unlocks audio once per page load.

Unlocking on the first input

Browsers' autoplay policy keeps an AudioContext suspended until the page receives a user gesture. The constructor only loads saved volumes and registers capture-phase, passive listeners for pointerdown, keydown, touchstart and mousedown. The first one calls unlock() (AudioSystem.ts:47), which builds the graph inside the gesture handler:

        const ctx = new C();
        const comp = ctx.createDynamicsCompressor();
        comp.threshold.value = -16; comp.knee.value = 12; comp.ratio.value = 5;
        comp.attack.value = 0.004; comp.release.value = 0.2;
        const master = ctx.createGain(); master.gain.value = 0.9;
        const sfxBus = ctx.createGain(); sfxBus.gain.value = this.vol.sfx;
        const musicBus = ctx.createGain(); musicBus.gain.value = this.vol.music * 0.7;
        sfxBus.connect(master); musicBus.connect(master); master.connect(comp); comp.connect(ctx.destination);

(AudioSystem.ts:53). C is AudioContext or the older webkitAudioContext. Once the context reports running, the gesture listeners are removed and any music requested earlier starts. Until then play() is a no-op and playMusic(key) only records wantMusic, which is why the title theme begins on your first click or key press. A visibilitychange listener suspends the context while the tab is hidden and resumes it on return.

Volumes

Defaults are SFX 0.7 and music 0.4, stored as { sfx, music } in localStorage["arcana-audio"]. setVolumes moves the bus gains with setTargetAtTime (time constants 0.03 s and 0.05 s) rather than jumping, so dragging the Settings sliders does not crackle. The music bus is always music × 0.7: songs are mixed hotter than effects, and the factor keeps the slider's 100% from burying combat sounds. The Settings sliders also save the pair to localStorage["arcana-ui-volumes"], and TitleScene and UIRoot re-apply that copy through applySavedVolumes (miscWindows.ts:18); both stores always hold the same values.

The synth toolkit

synth.ts exports three voice builders. Each takes a SynthCtx ({ ctx, out, t0 }: the context, the node to connect to, and a start time on the audio clock) and schedules everything up front: start, stop, envelope and glides are all set as automation events, so nothing runs in JavaScript while the sound plays.

  • tone(s, opts) (synth.ts:86): one oscillator (sine, triangle, square, sawtooth) with an optional pitch glide (f → f2, exponential by default), detune, vibrato (a second oscillator, the LFO, modulating detune in cents and fading in after delay), an optional biquad filter with its own cutoff sweep, stereo pan, and the envelope.
  • noise(s, opts) (synth.ts:117): a looping 2-second white-noise buffer, created once per context and cached in a WeakMap, started at a random offset so repeated hits never sound identical, through up to two filters.
  • bell(s, f, t, dur, v, ratio, index) (synth.ts:136): two-operator FM (frequency modulation): a modulator at f × ratio wobbles the carrier's frequency by up to f × index Hz, decaying to 5% over the note, which gives the bright-then-pure strike of a bell.

All three share one envelope:

function envelope(g: GainNode, t: number, v: number, a: number, hold: number, dur: number, release: 'exp' | 'lin' = 'exp') {
  const p = g.gain;
  p.setValueAtTime(0.0001, t);
  p.linearRampToValueAtTime(Math.max(0.0002, v), t + Math.max(0.002, a));
  if (hold > 0) p.setValueAtTime(Math.max(0.0002, v), t + a + hold);
  if (release === 'lin') p.linearRampToValueAtTime(0.0001, t + dur);
  else p.exponentialRampToValueAtTime(0.0001, t + dur);
}

(synth.ts:59). The floor of 0.0001 rather than 0 is required: exponentialRampToValueAtTime cannot reach or start from zero. Notes are written by name: noteFreq("C#5") converts to MIDI and then to Hz with A4 = 440. shaperCurve(amount) returns a cached soft-clip curve for a WaveShaperNode, used by the SFX for grit.

Sound effects

SfxKey has 35 members (types.ts:261), and SFX (sfx.ts:27) is a Record<SfxKey, SfxRecipe>, so TypeScript fails the build if a key has no recipe. A recipe gets the synth context, a pitch multiplier p and a volume multiplier v. Gameplay code never builds sounds; it names one, either directly (audio.play('levelup')) or through data, as each skill definition does with its sfx field (the most used are buff, cast_holy, cast_shadow and cast_fire).

The Holy, Shadow and curse voices

When the Holy and Shadow Schools were added (Phase 3), the contract added three keys before anyone had designed them, and the first version aliased existing recipes: cast_holy was heal pitched up, cast_shadow and curse were whoosh pitched down. Commit c09fa9c replaced the aliases with bespoke voices written by Codex (sfx.ts:217):

  cast_holy: (s, p, v) => {
    // Soft choir triad with octave air and quiet, harmonic bell shimmer.
    ['C5', 'E5', 'G5'].forEach((n, i) => {
      const f = N(n) * p;
      tone(s, { type: 'sine', f, t: i * 0.015, dur: 0.5 - i * 0.015, v: 0.055 * v, a: 0.07, hold: 0.04, detune: (i - 1) * 4, vib: { rate: 5, depth: 7, delay: 0.06 } });
      tone(s, { type: 'sine', f: f * 2, t: i * 0.015, dur: 0.46 - i * 0.015, v: 0.015 * v, a: 0.09, detune: (1 - i) * 5 });
      bell(s, f * 2, 0.06 + i * 0.025, 0.4 - i * 0.025, 0.018 * v, 2, 0.45);
    });
    noise(s, { dur: 0.5, v: 0.025 * v, a: 0.09, filter: { type: 'highpass', f: 5500 * p } });
  },

cast_shadow is a breathy falling sweep: two sawtooths a minor second apart (D3 gliding to Db3, detuned ±9 cents) through a closing lowpass and a light waveshaper, under bandpassed noise sweeping down from 900 Hz. curse is a descending tritone (B4 → F4 over a B3 → F3 shadow) with wide, uneasy vibrato and a fading hiss. Each sets the mood of its School with intervals: a major triad for Holy, a minor second and a tritone for Shadow.

Rate limits and the voice budget

A chain-lightning cast can produce dozens of hits in a few frames. play() (AudioSystem.ts:87) applies three limits before building anything:

    // global voice budget
    this.recent = this.recent.filter(t => nowMs - t < 100);
    if (this.recent.length >= 14) return;
    // per-key rate limit
    const [gap, per100] = SFX_LIMIT[key] ?? [25, 3];
    const hist = (this.lastPlay.get(key) ?? []).filter(t => nowMs - t < 100);
    if (hist.length && nowMs - hist[hist.length - 1] < gap) return;
    if (hist.length >= per100) return;
    // …
      // the more copies of this key are ringing, the quieter each new one is
      out.gain.value = 1 / Math.sqrt(hist.length);
  • At most 14 SFX starts per 100 ms in total.
  • Per key, a minimum gap and a maximum per 100 ms from SFX_LIMIT (sfx.ts:256), for example monster_hit [28 ms, 4], thunder [140 ms, 1], job_advance [1000 ms, 1]; unlisted keys get [25 ms, 3].
  • The n-th copy of a key within 100 ms plays at 1/√n, so a burst sounds denser rather than louder.

Each play gets its own output gain (also scaled by SFX_GAIN[key], default 0.85, and the caller's volume), starts 5 ms in the future (t0 = ctx.currentTime + 0.005) so all of its voices are scheduled before the first one sounds, and is disconnected after 4 s; the longest recipe, job_advance, ends at about 2.7 s.

Songs as text

A song (music.ts:17) is a tempo, a metre, a resolution (res: 2: eighth-note steps), one chord per bar, and pattern strings with one token per step. Melody tokens are note names, - holds, . rests; bass uses R/3/5/O (root, third, fifth, octave) relative to the current chord; arpeggios use chord-tone indexes; drums use x and o (accent or open hat). | is a bar line for readability. The title theme (music.ts:38):

    lead: 'brass', leadVol: 0.13,
    // …
    bass: { pattern: ['R - - - - - 5 -', 'R - - - 5 - - -'], inst: 'tri', octave: 2, vol: 0.32 },
    pad: { octave: 4, cutoff: 1800, vol: 0.05 },
    arp: { pattern: ['0 1 2 3 2 1 2 3'], octave: 5, inst: 'pluck', vol: 0.04, everyOther: true },
    drums: { kick: ['x . . . x . . .'], snare: ['. . . . . . . .', '. . . . . . x x'], hat: ['. . x . . . x .'], vol: 0.8, crashOnLoop: true },
    echo: { time: 0.33, feedback: 0.25, mix: 0.18 },

compile() (music.ts:269) turns this once per song into per-step arrays: the chord at each step (a bar with two chord names is split evenly), where chord segments start, and the notes that begin on each step with their lengths. Patterns shorter than the song (bass, drums, arp) are cycled per bar. Instruments are small recipes over tone and bell: the flute is a sine with delayed vibrato plus a quiet octave triangle, the brass two detuned sawtooths through an opening lowpass, the pad three chord tones each doubled at ±6 cents with a slow linear-release envelope.

The lookahead sequencer

SongPlayer (music.ts:428) does not play notes when a timer fires; it uses the timer to schedule notes slightly in the future on the audio clock, the standard WebAudio pattern for steady timing:

  private tick() {
    if (this.stopped && !this.timer) return;
    const ctx = this.ctx;
    if (ctx.state !== 'running') return;
    const now = ctx.currentTime;
    // After a stall (background tab), skip ahead instead of bursting.
    if (this.nextTime < now - 0.25) this.nextTime = now + 0.05;
    const stepDur = 60 / this.song.def.bpm / this.song.def.res;
    let guard = 0;
    while (this.nextTime < now + 0.14 && guard++ < 32) {
      if (!this.stopped) {
        try { this.playStep(this.step, this.nextTime, stepDur); } catch (e) { console.warn('[music] step failed', e); }
      }
      this.nextTime += stepDur;
      this.step++;
      if (this.step >= this.song.totalSteps) { this.step = 0; this.pass++; }
    }
  }

(music.ts:481). A setInterval fires every 25 ms; each tick schedules every step whose start time falls within the next 0.14 s. Looping is just the step counter wrapping; pass counts loops and drives variation: counter-melodies and arpeggios marked everyOther play only on odd passes, leadOctaveUpOnRepeat doubles the lead's frequency on odd passes, and crashOnLoop hits a cymbal on step 0 from the second pass. Melody notes are humanised by up to ±3 ms and shortened to 92% of their written length so repeated notes re-articulate.

Switching songs. playMusic(key) ignores a request for the song already playing (so walking between two boss maps does not restart it). Otherwise startSong tells the old player to fade out over 1.2 s (CROSSFADE) and starts the new one fading in over the same time, or over 0.8 s if nothing was playing. Each SongPlayer has its own bus, so the two overlap cleanly; the old one disconnects its nodes 0.6 s after its fade ends.

Advanced: scheduling ahead with currentTime
  • Two clocks. JavaScript timers (setInterval) are imprecise and pause in background tabs; AudioContext.currentTime runs on the audio thread and is sample-accurate. The sequencer reads the audio clock and only uses the JS timer to wake up. The 0.14 s window is larger than several timer periods (25 ms), so a late timer still finds the next steps unscheduled and schedules them in time.
  • Latency vs. robustness. A larger window survives longer main-thread stalls (a heavy art generation frame) but delays tempo changes and stops. Here nothing changes mid-song except stopping, and stop is a gain fade, so 0.14 s is safe.
  • Stalls. If the tab was hidden and nextTime fell more than 0.25 s behind, the sequencer jumps ahead instead of scheduling the missed steps all at once. The guard caps a tick at 32 steps for the same reason. Hidden tabs also suspend the context entirely (visibilitychange), and tick() does nothing unless the context is running.
  • SFX use the same idea in miniature: every voice of a recipe is scheduled relative to one t0 5 ms ahead, so a chord's notes start on the same sample.
Advanced: avoiding clicks

A click is a sudden jump in the waveform. The code avoids every common source:

  • Every envelope starts at 0.0001 and ramps up over at least 2 ms; every release ramps down to 0.0001 before the source stops. Oscillators stop at dur + 0.05, after the gain is already silent.
  • Song fades and volume changes are automation ramps (exponentialRampToValueAtTime, setTargetAtTime), never direct .value writes on a running bus. stop() first pins the current value with setValueAtTime(g.value) after cancelScheduledValues, so the fade starts from where the gain actually is.
  • Noise voices get the same envelope as oscillators, so even an 8 ms crackle tick fades in and out rather than switching on and off.
  • The master DynamicsCompressor (threshold −16 dB, ratio 5, 4 ms attack) catches peaks when many voices sum, which would otherwise clip at the output.
Advanced: CPU cost and the autoplay policy
  • Node churn. Every note creates fresh nodes: a tone is an oscillator and a gain, plus a filter, an LFO pair and a panner when asked for. A pad hit is 6 oscillators with 6 filters, and a busy step of the boss theme (lead and counter, bass, pad, arp, three drums) creates a few dozen nodes every 0.18 s. Nodes are cheap but not free; the browser frees them after they stop. This is why SFX have hard caps (14 per 100 ms) and why the noise buffer and shaper curves are cached rather than rebuilt.
  • Main-thread work is tiny. JavaScript only creates nodes and automation events; the audio thread does the synthesis. A dropped game frame does not glitch audio unless it outlasts the 0.14 s lookahead.
  • Autoplay. Creating the context inside the first gesture handler is the reliable way to start audio in every browser. Code that plays a sound before that (title music, UI clicks) silently does nothing, and music is remembered and started on unlock. If you add a new entry point that should make sound, call getAudio() rather than creating an AudioContext, or a second context would need its own unlock.
  • Adding a sound: add the key to SfxKey in src/core/types.ts, a recipe to SFX (the Record type forces it), and if it can fire in bursts, a SFX_LIMIT entry. Keep total length under the 4 s disconnect.
